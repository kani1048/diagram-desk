# 独立した設計ルールセットと DDD 検証

## 目的・範囲

- 書式・参照整合性の検証は既存の形式側に維持する。
- 検証側で対応アーキテクチャを宣言するルールセット登録と実行基盤を追加する。
- Onion を中立な検証用モデルへ変換するアダプターと、Onion を import しない DDD ルールを分離する。
- CLI の --rules（複数指定可）で追加検証を選択し、未知・未対応ルールは明示的に失敗させる。
- DDD の集約・ルートなどの宣言は独立した設定ファイルで渡し、Onion の書式には DDD を追加しない。
- 不足情報と実際の違反を区別し、ファイル・Pointer・ルールの診断を JSON で返す。
- DDD の全設計判断を自動判定したとは扱わず、検証できる宣言と関係だけを対象にする。

## base・レビュー単位

PR #3 の形式分離と CLI 検証を前提とする。base は docs/diagram-responsibilities。
今回の PR は独立した追加機能の差分だけを持つ。PR #3 は変更しない。

## 検証計画

- DDD 正常例・集約ルート／メンバーの誤宣言・外部から集約内部への依存・コンテキスト越境。
- 宣言不足、設定誤記、未知のルール、未対応形式、複数ルールの選択、構造不正時の追加検証抑止。
- CLI の複数ファイル・設定・診断・終了コード、従来の検証出力の互換性。
- ルール追加のテストで Onion と DDD の相互依存がないことを確認。
- Node 22 で全テスト、Schema の生成一致、Docker の本番依存で CLI を検証。
