# 図の責務と受け渡し契約の整理

## 目的

エージェントが正本のソースを更新し、人間が Diagram Desk の図で確認する流れを優先する。
図の内容・図の表現・閲覧の場の3つの責務と、各境界の契約を文書にする。

## 範囲

- 現行の描画アダプターと更新反映の構成を調べる。
- 責務、現行契約、目標とする契約、Onion/VPD の移行順を設計文書に記す。
- README から設計文書へ案内する。
- 本単位では実行コードの変更、描画の外部パッケージ化、VPD 接続は行わない。

## 検証計画

- 文書中の現行仕様を main のコードと照合する。
- ローカルリンクの存在、差分の空白、変更範囲を確認する。
- 文書変更のみなので実行テストの追加・実行は不要。

## 状態

完了。`docs/diagram-responsibilities.md` に決定事項・現行契約・追加する確認情報・Onion/VPD の移行順を記載し、README からリンクした。

検証: 現行 main の形式登録・描画アダプター・Viewer・SSE と照合。ローカルリンクの存在、`git diff --check`、文書のみの変更範囲を確認した。実行コードの変更がないためテストは実行していない。

追補: 外部入力（`.mmd`、将来の `.svg` など）と内部の SVG 表示契約を分離。Mermaid エンジンと Desk のアダプターの責務、対応形式を追加する条件を明記した。実行コードの対応形式は変更していない。
